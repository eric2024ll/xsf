# 20260813 书架管理 + 批量 BibTeX 导入 + OCR 配置 + 改名

## 问题

1. 书架（collection）全局选择器在导航栏，跳转逻辑让人困惑
2. 文献列表页缺少批量导入 BibTeX 元数据的能力
3. 重 OCR 报错 `PADDLE_OCR_TOKEN 环境变量未设置`，用户需在前端配置 OCR API
4. 应用名「架閣」改为「小書房」

## 改动

### 书架管理重构

- 导航栏删除全局 collection `<select>` + ☰ 新建按钮，collection 管理统一到书架页（首页）
- 书架列表：每行「进入·改名·删除」，末尾「+ 新建书架」
- 新增 3 个 API：`POST /api/collections/{c}`（建库+init_db）、`DELETE`（rmtree）、`PATCH`（rename 移目录）
- 新建书架先调 init_db 建表再跳转，避免空 DB 被误判

### 批量 BibTeX 导入

- `bib_utils.py` 新增 `parse_bib_entries`（手写正理解析 @type{...}）、`normalize_title`（繁→简+去标点）、`match_docs_to_entries`（exact+substring 模糊匹配）
- 匹配逻辑：doc 标题 / filename stem 与 entry 标题归一化后比较，单候选→matched，多候选→ambiguous，无候选→unmatched
- 新增 `POST /docs/match-bib`（解析+匹配）、`POST /docs/batch-patch`（批量写入 bib_type+bib_data+cite_key）
- 文献列表页加「批量导入 BibTeX」按钮 + 模态框（粘贴/上传→审查表三区→应用）

### OCR 前端配置

- 服务端 `ocr-config.json`（chmod 600，原子写），`get_ocr_token()` 配置文件优先、环境变量 fallback
- 新增 `GET/POST /api/ocr-config`（不泄露 token 明文）+ `POST /api/ocr-config/test`（空白 PDF 提交验证）
- 上传页 Tab3「OCR 设置」：provider 标签 + token password 输入 + 测试连通 + 保存

### 改名 架閣 → 小書房

- 18 文件改名（8 模板品牌/title、api.py FastAPI title、README、pyproject、cli、scripts、app.css）
- login subtitle「放書架的地方，也能看書」保留不变
- 包名/目录/env 变量（jiage, JIAGE_*）不改——技术标识符

## 决策

- 书架管理放书架页而非导航栏：导航栏全局 coll 切换逻辑混乱，收敛到单一入口
- OCR 仅 PaddleOCR-VL：能输出坐标（bbox 硬需求）的 provider 有限，先做这一个
- OCR 配置服务端存储：全局设置一次，不每次上传时选
- 批量 bib 匹配用 substring 为主力：doc 标题常比 entry 标题短（如「台蕃采风录」vs「台蕃采风录（附照片、图）」）
